# Exact pins, deliberately. This repository's PDF pipeline is built around
# byte-reproducible output -- Scripts/package.json already pins Puppeteer and the
# exact Chrome build for the same reason -- and these packages sit directly in
# that path: `markdown` renders the HTML every PDF is printed from, and `pypdf`
# rewrites the metadata that makes the result reproducible. A floating `>=` here
# meant an upstream release could change committed PDF bytes with no change to
# this repository.
#
# It was not hypothetical. When these pins were introduced, a maintainer's
# machine had markdown 3.10.2 / pypdf 6.13.2 / pymupdf 1.28.0 while CI resolved
# 3.10.3 / 6.16.2 / 1.28.2, so local regeneration and CI regeneration were not
# running the same pipeline.
#
# The versions below are the set CI resolved on 2026-09-01, in a run where
# `Scripts/_verify_pdf_reproducible.py` passed. Pinning to CI's set rather than
# the newest releases keeps local output matching what CI regenerates on a study
# pull request.
#
# To bump: edit a version, then let `pdf-pipeline-smoke.yml` run (it triggers on
# this file) and regenerate any study whose PDF changes, in the same pull
# request. Never bump a version and committed PDFs in separate commits.

# Required, not optional. _study_catalog.py and _bootstrap_proposal_study.py both
# do ZoneInfo("Asia/Kolkata") at import time, and Windows ships no system tz
# database -- so without this, a fresh `pip install -r requirements.txt` on
# Windows fails on almost every script in Scripts/. It went undeclared for as long
# as it did because Linux CI falls back to /usr/share/zoneinfo and maintainers had
# it installed as somebody else's transitive. Listed unconditionally so the tz
# database is a pinned input rather than a property of the host.
