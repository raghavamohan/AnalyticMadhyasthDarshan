Site APIs

Read access is public and needs no account or API key. Use the HTTP API for catalog search and study metadata, or MCP for the same read operations and Markdown resources. Submission and discussion writes use separate human sign-in flows. This guide describes the repository contract; health endpoints report runtime readiness, and the OpenAPI documents define individual operations.

Agents should start at /.well-known/api-catalog (RFC 9727). Public reader skills are listed at /.well-known/agent-skills/index.json. The MCP Server Card is at /.well-known/mcp/server-card.json (SEP-1649). Web Bot Auth keys are at /.well-known/http-message-signatures-directory. In-browser agents can call catalog search, retrieval, and navigation tools through WebMCP (/webmcp.js). DNS for AI Discovery (DNS-AID) publishes ServiceMode HTTPS records at _index._agents.analyticmadhyasthdarshan.org. The catalog linkset points at the published studies catalog JSON for reading papers, and at the submission and discussion HTTP APIs for writes. Identity policy is at /auth.md (Auth.md).

Studies catalog

The public collection is JSON arrays the studies landing page already fetches, plus a unified file and an HTTP search that matches WebMCP search_studies. Each row has slug, title, status (ongoing, draft, or released), and, when a document exists, relative html, pdf, and md paths. Markdown is the source of truth. Resolve those paths against https://analyticmadhyasthdarshan.org/Studies/ (applied studies use ../Applications/<Slug>/).

Read examples and pagination

These PowerShell examples make anonymous read requests. HTTP search matches catalog titles, slugs, descriptions, and categories; it does not search the full study body. Collection filters are topical, formal, and applied; status filters are ongoing, draft, and released. The website labels ongoing work as Planned. 

$base = "https://analyticmadhyasthdarshan.org"
$page = Invoke-RestMethod "$base/api/studies?q=coexistence&limit=10&offset=0"
$page.studies | Select-Object title, slug, status, mdUrl

$study = Invoke-RestMethod "$base/api/studies/The-Ontology-of-Coexistence"
$study.outline
if ($study.mdUrl) {
    $markdown = Invoke-RestMethod $study.mdUrl
}
Invoke-RestMethod "$base/api/cite/The-Ontology-of-Coexistence"
Invoke-RestMethod "$base/api/glossary?q=jeevan"

Study and glossary lists default to 50 rows; limit accepts 1–100 and offset accepts 0–10,000. Responses contain count (this page), total (all matches), limit, offset, hasMore, and nextOffset. Follow nextOffset with the same filters while hasMore is true. Search text is limited to 200 characters. Static catalog JSON files return complete arrays without pagination. 

$rows = @()
$offset = 0
do {
    $page = Invoke-RestMethod "$base/api/studies?limit=100&offset=$offset"
    $rows += $page.studies
    $offset = $page.nextOffset
} while ($page.hasMore)
if ($rows.Count -ne $page.total) {
    throw "The catalog changed during pagination; reload before counting."
}

Dynamic results provide absolute htmlUrl, pdfUrl, and mdUrl values. Follow these URLs as returned: they can include an r query parameter that selects the publication revision used for the metadata. Ongoing entries return null document URLs and an empty outline; citation and Markdown-resource requests for them fail. An empty outline can also mean Markdown retrieval failed, so it does not prove a paper has no headings. Retrieve the body before making claims beyond the catalog description.

Submission portal

Base URL: https://api.analyticmadhyasthdarshan.org. Contributors sign in with GitHub to propose studies, submit or revise drafts, update study and companion sources, request deletion, and change Draft/Released status. Accepted writes create or update GitHub work for review; they do not publish immediately. Reading published studies does not use this API.

ResourceURL
OpenAPI description /openapi/submissions.json
Health GET /api/health
Maintainer notes infra/worker/README.md

Write routes require a first-party session cookie from GitHub OAuth and a Cloudflare Turnstile token. POST /api/notify is a server-to-server hook authenticated with a shared secret, not a public client.

Contribution writes also require a client-generated UUIDv4 operationId. Check an interrupted proposal, submission, revision, status change, or deletion through GET /api/operation?id=…; its state is notStarted, inProgress, complete, or uncertain. Retry only an unchanged operation whose state is notStarted.

Human write requirements

Use the portal or discussion page for sign-in. Authenticated operations require the appropriate session cookie. All browser POSTs require a trusted Origin and Content-Type: application/json, including magic-link requests and logout. The portal's cross-origin requests to the API subdomain include credentials. Turnstile is required for proposal, submission, revision, status, deletion, and magic-link requests; it is not repeated for signed-in comments, moderation, notification preferences, or logout. The CI-only POST /api/notify uses X-Notify-Secret instead of a browser session.

Load the current source identifier before an update or deletion: sourceSha for study/companion files and figure replacements, sourceVersion for notification preferences, and sourceUpdatedAt for comment hide/delete. A stale request returns 409 with details.currentSource; reload and reconcile the change. Contribution receipts and unchanged payloads must be retained across interrupted requests. See contributor recovery.

Submission and revision JSON bodies are capped at 20,000,000 UTF-8 bytes; other submission writes at 65,536 bytes, and discussion writes at 16,384 bytes. Markdown sources and individual figures are limited to 2 MiB, PPTX sources to 10 MiB. Up to 20 figures can accompany a submission; supplementary figures and presenter Markdown share a 4 MiB base64-character budget (approximately 3 MiB decoded). The complete JSON envelope must also fit. Exact fields, filenames, ownership requirements, and per-operation limits are in OpenAPI.

Error responses

Every JSON HTTP error from the Studies, submission, and discussion APIs uses the same envelope. Success responses are unchanged. The X-Request-ID header always matches requestId in the body and can be included in an issue report. Submission and discussion responses are private and use Cache-Control: private, no-store; public Studies API errors use Cache-Control: no-store. 

{
  "success": false,
  "code": "invalid_request",
  "message": "The request is invalid.",
  "requestId": "01JABCDEFGHJKMNPQRSTVWXYZ12",
  "details": {}
}

details is optional. MCP JSON-RPC failures retain the protocol's required error object and place the correlation value at error.data.requestId. The reusable status responses and exact schemas are in the three OpenAPI documents above.

Dynamic APIs advertise a shared edge policy of 40 requests per IP per 10 seconds in RateLimit-Policy. Contribution writes additionally allow 30 new attempts per account per UTC hour; magic links allow five per email per hour. Those responses include quota state in RateLimit. Honor Retry-After on 429. Edge-generated blocks may return HTML instead of the Worker error envelope; report the status, content type, endpoint, and available request ID rather than treating HTML as JSON. Health responses use HTTP 200 with a body status of ok or degraded; inspect the body. Operator guidance is in Public API operations.

DNS for AI Discovery (DNS-AID)

Agents can discover this site from DNS before any HTTP round-trip. Query ServiceMode HTTPS records under _agents.analyticmadhyasthdarshan.org (draft-mozleywilliams-dnsop-dnsaid, RFC 9460). MCP

POST /mcp is Streamable HTTP JSON-RPC (read-only). Tools: search_studies, list_studies, get_study, get_study_outline, get_glossary, get_start_here, get_cite. Resources: studies://catalog-all, studies://glossary, studies://feed, studies://start-here, and studies://study/{slug} for canonical markdown. The Server Card is /.well-known/mcp/server-card.json. There are no write tools.

This is a stateless JSON-response transport: send JSON-RPC requests by POST with Content-Type: application/json and initialize before using tools. Supported protocol versions are 2025-06-18, 2025-03-26, and 2024-11-05. There is no persistent session ID or GET/SSE stream; GET /mcp returns 405. Notifications receive HTTP 202 with no body. Request bodies are limited to 64 KiB. Discover exact tool inputs through tools/list; tool payloads are objects in result.structuredContent and JSON text in result.content. A tool failure can set result.isError even when HTTP status is 200. 

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "initialize",
  "params": {
    "protocolVersion": "2025-06-18",
    "capabilities": {},
    "clientInfo": { "name": "study-reader", "version": "1.0" }
  }
}

WebMCP is a separate browser interface, enabled only where navigator.modelContext.registerTool is available. Its tools are search_studies, list_studies, get_study, open_study, and open_page. These tools use the page's catalog and navigation; they do not expose the full remote MCP tool set.

Reusable agent prompt

Copy this prompt into an agent with HTTP or MCP access, and replace the task on the last line. It includes validation steps for catalog-wide answers so a row cannot be silently omitted during summarisation. 

You are a research agent using the public Analytic Madhyasth Darshan Agent API.

Base URL: https://analyticmadhyasthdarshan.org

1. Discover the current API before working:
   - https://analyticmadhyasthdarshan.org/.well-known/api-catalog
   - https://analyticmadhyasthdarshan.org/.well-known/mcp/server-card.json
   - https://analyticmadhyasthdarshan.org/openapi/studies.json

2. Prefer Streamable HTTP MCP at https://analyticmadhyasthdarshan.org/mcp
   when your environment supports it. Available read tools are
   search_studies, list_studies, get_study, get_study_outline, get_glossary,
   get_start_here, and get_cite.

3. Otherwise use the public HTTP API:
   - GET /api/studies?q=<query>
   - GET /api/studies/{slug}
   - GET /api/glossary?q=<term>
   - GET /api/start-here
   - GET /api/cite/{slug}

4. Search for relevant studies first. Follow nextOffset while hasMore is true,
   and use collection and status filters where useful. For a catalog-wide
   answer, request pages up to limit=100, calculate counts from the returned
   rows, and verify that every group count and enumerated row reconciles with
   the response total before answering. Do not count rows manually.

5. Retrieve each selected study's metadata and outline, then its canonical
   Markdown through studies://study/{slug} or the returned mdUrl. Markdown is
   the source of truth. Do not make claims beyond a catalog description unless
   you retrieved the study body; label a description-only summary as such.

6. Use the glossary for unfamiliar terminology and preserve important original
   terms such as satta and jeevan. Use get_cite or /api/cite/{slug} for
   citations. Identify sources by title and slug and include stable links.

7. Distinguish Ongoing, Draft, and Released studies. Do not present Draft work
   as final, and do not assume an Ongoing study has a complete document.

8. Separate statements made by a study from your synthesis or inference. State
   when the retrieved sources do not establish an answer.

9. This is a read-only agent workflow. Do not attempt submission, discussion,
   or other write APIs. Never request cookies, credentials, Turnstile tokens,
   or shared secrets from the user.

10. On HTTP 429, honor Retry-After. On failure, report the endpoint, status,
    error code, and request ID. If a JSON endpoint instead returns HTML or a
    Cloudflare challenge, report an edge-access failure; do not interpret it as
    an empty API response. If your client blocks a constructed URL, describe
    that as a client restriction rather than an API failure. Never fabricate a
    response.

Return a direct answer, evidence grouped by study, citations and source links,
and any limitations, disagreements, or unresolved questions.

Task: [INSERT THE QUESTION OR RESEARCH TASK HERE]

Agent Skills Discovery

GET and HEAD /.well-known/agent-skills/index.json return the Agent Skills Discovery index of public reader skills (start-here, cite-study, compare-traditions). Maintainer skills that need a git clone live in /.well-known/agent-skills/index-maintainer.json. Each entry is a SKILL.md with a SHA-256 digest.

Catalog document

GET and HEAD /.well-known/api-catalog return an RFC 9727 linkset (Content-Type: application/linkset+json) listing the studies catalog JSON and each write API’s service-desc, service-doc, and optional status links, following RFC 9727.
